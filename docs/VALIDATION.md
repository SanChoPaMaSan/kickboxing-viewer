# 검증 기록

검증일: 2026-11-01~02, Windows, Node.js 24.18.0, npm 11.16.0. 브라우저는 Codex in-app Chromium입니다.

## 자동 검사

- `npm test`: 6개 테스트 통과. 10개 카드/좌우 순서, 가드 시작·종료, 240개 시간 샘플의 연속·유한 좌표, 선택 부위 이동과 반대쪽 유지, 미들킥/로우킥 높이 및 훅/어퍼컷 궤적 차이, 관절 도달 범위, IK 길이 검증.
- `npm run build`: TypeScript 검사 및 Vite 프로덕션 빌드 성공.
- 최초 검사에서 어퍼컷 이동 폭과 스트레이트의 다리 도달 범위 실패를 발견하고 좌표를 수정한 후 통과.
- 빌드 경고: Three.js를 포함한 JS 약 741 KB / gzip 201 KB로 Vite 500 KB 권고를 초과. 빌드 오류는 아님.

## 실제 브라우저 검사

- 잽만 구현한 시제품에서 캐릭터 표시, 카드 클릭, 재생 완료(100%)를 확인한 뒤 확장.
- 완성본 10개 카드를 모두 클릭하고 각 기술·좌우 이름이 맞는지 확인. 빠르게 연속 선택해도 단일 선택 상태 유지.
- 각 기술을 0.5배속으로 재생하고 약 53~54%에서 정지하여 타격 순간을 캡처. `screenshots/`에 10개 원본과 비교 이미지 저장.
- 연두색 왼손/흰색 오른손, 좌우 킥 및 타격 높이 차이를 캡처로 검토. 단순화된 시각화이며 전문가의 정확성 검증은 아님.
- 일시정지 후 진행률 41%가 400ms 뒤에도 유지. 재개 후 100% 완료 확인.
- 반복 ON에서 2.4초 사이클 이후 진행률이 30%로 돌아오고 재생 유지 확인.
- 다시 재생, 0.5배속/1배속 변경, 마우스 드래그 회전, 휠 확대, 시점 초기화 확인.
- 390×844 뷰포트에서 카드가 캐릭터 아래 좌우 두 열로 유지됨. 문서 너비 375px로 가로 넘침 없음. 모바일 전체 캡처 검토.
- 기본 데스크톱 전체 화면 캡처 검토.
- 콘솔 오류·경고 조회 결과 빈 목록. 외부 모델 파일 요청은 설계상 없음.
- 실제 빌드 결과를 `npm run preview -- --port 4173 --strictPort --base=/kickboxing-viewer/`로 열고 `/kickboxing-viewer/` 하위 경로에서 UI·3D 로딩 및 재생 제어 확인. 콘솔 오류 없음.

## 아직 검증하지 않은 것

- GitHub Actions 실제 실행, 원격 저장소 push, 공개 Pages URL 및 push 후 사이트 갱신.
- 실제 스마트폰의 터치/성능, Safari/Firefox, GPU별 호환성.
- WebGL 실패 안내는 구현했으나 고의적인 GPU context loss 테스트는 수행하지 않음.
- 전문가의 동작 정확성, 모든 전환의 자기 충돌 및 생체역학 검증.

## 제출 증거

`screenshots/desktop.jpg`, `mobile.jpg`, 기술별 타격 순간 JPG를 활용할 수 있습니다. 배포 후 저장소 화면, Actions 성공 화면, 배포 URL에서 실행 중인 화면을 추가 촬영하세요. 로컬 화면을 공개 배포 성공 증거로 사용하지 마세요.
